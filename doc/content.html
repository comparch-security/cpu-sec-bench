Security Test Benchmark — Documentation

This benchmark evaluates the security features a processor hardware platform actually provides. Each test case is a short, deliberately malformed C++ program that attempts one specific vulnerability; if the attack succeeds, the platform lacks the corresponding defense, and the case reports that by exiting 0. The suite runs across several instruction sets and operating systems on top of a shared per-platform support library.

For installation and first-run instructions see README.md. For the design rationale behind the test cases see INTERNAL.md — note that its counts and case names predate the current suite and have drifted from configure.json.

Current suite

Category Directory What it covers
Memory spatial safety mss/ Out-of-bounds and cross-boundary access on stack, heap, global data and read-only data; object, frame, page and section boundaries; type conversion; and spray writes.
Memory temporal safety mts/ Use-after-free, use-after-reclaim and double-free on heap and stack, including the reclaim calibration cases the others depend on.
Access control acc/ Address-space randomization, code-page readability, the GOT, inter-object and intra-object redzones, and the calibration helpers that measure frame size, return-address offset and other runtime parameters.
Pointer integrity cpi/ Function pointers, vtable pointers and the global offset table — the pointers whose alteration most control-flow attacks depend on.
Control-flow integrity cfi/ Return-address hijacking (backward-edge), indirect call and jump hijacking (forward-edge), vtable forgery and substitution, argument-type confusion, and code injection into stack, heap, data and read-only data.

The registry configure.json is the authoritative list of what the suite contains, and script/check_catalog.py derives the current counts from it; the Test Catalog lists every case.

A program is one .cpp source file testing one vulnerability. A record is one entry in configure.json: a program combined with a particular set of compile-time macros and runtime arguments. One program therefore yields several records where it is exercised in different memory regions or both overflow directions.
