## Summary

The repository is a public cross-platform security test benchmark (`github.com:comparch-security/cpu-sec-bench`) that has never been Claude-initialized: it has no `CLAUDE.md`, no `.claude/`, no `tmp/` working area, and no documentation tree. The project carries a 48 KB internals narrative (`INTERNAL.md`), a user-facing `README.md`, and a 191 KB machine-readable test registry (`configure.json`) — but no browsable documentation and no Claude-facing guide. This plan creates both.

**Design decisions taken with the user**

The user confirmed **public mode** explicitly, which is the confirmation the global rule requires before a root `CLAUDE.md` becomes git-tracked. So `CLAUDE.md` and `.claude/mega-audit-files.json` are tracked and visible to the project's outside contributors; the repo openly acknowledges Claude tooling. Note that `detect_repo_mode.py` reports `public` here only because `.claude/` happens to not be gitignored — the repo is *uninitialized*, not configured, so the mode was a genuine decision rather than a detection result.

The user chose **substantive core pages** for `doc/` (not stubs, and not a revival of the 2,052-line historical LaTeX specification), and a **curated test catalog guarded by a scripted coverage check** (rather than a generator script that would add a source file and a build step).

**Data flow of the catalog check.** The catalog lists all 246 `configure.json` records over 103 programs; the scripted check re-reads `configure.json` and asserts **two-way set equality** over both sets — every record and program name must match the page exactly, so a future test-case addition **or removal** that forgets the catalog fails a re-runnable check rather than silently drifting.

**Source-of-truth discipline.** Every name and count in `CLAUDE.md` and `doc/` is derived from `configure.json` (246 records over 103 programs), `Makefile`, `scheduler/run-test.cpp` and `lib/`. Two existing documents have drifted and are handled differently, deliberately. `INTERNAL.md` is treated as *prose only*: it is accurate about rationale but wrong on facts — it states "221 test cases" and uses pre-2021 case names (`read-cross-page-index`, `spray-cross-object-stack`) that no longer exist in `configure.json`. (Not every name in it is stale — `mts-double-free`, for one, is still current.) It is outside the planner's Write/Edit allowlist, so it is **flagged, not fixed**. `README.md`'s user-facing "Test results" table has also drifted — it documents eight result groups and omits `64–65`, which the scheduler emits — and because `README.md` *is* in the planner's scope and `doc/architecture.html` must document the same contract, **Step 8 repairs it** rather than flagging it. The historical `doc/specification.tex` (deleted 2021-02-08, recoverable at `80243fd:doc/specification.tex`) is deliberately *not* revived.

**Local, machine-generated directories.** Three directories at the repo root are machine-local and must never be committed: `tmp/` (the plans/reports/verification working area), `.codegraph/` (the CodeGraph index, which appeared during this planning session when the mega-audit lenses invoked the CodeGraph tools) and `trace-log/` (per-case run traces written by `lib/include/builtin.hpp`). `tmp/` and `.codegraph/` are added to `.gitignore` in Step 10 and `trace-log/` in Step 13. `.codegraph/` ships its own nested self-ignoring `.gitignore`, so the only file a naive sweep would actually stage is that 229-byte file — measured, not assumed — but the repo-level entry is what makes `git status --short` clean and the commit invariant checkable.

**How the bench works** (the model the new docs describe): each test case is a short, deliberately malformed C++ program targeting one vulnerability. The `Makefile` builds only the scheduler (`run-test`); test cases are compiled on demand by the scheduler itself, which reads `configure.json`, expands each record's `arguments` (`-r` range / `-l` list / `-v` variable), gates on the `require` prerequisite graph (inner list OR, outer list AND), builds with `make -B test/<program> <MACRO>=<value>` *only when the record's `conf-macro` set changes*, runs the binary, and interprets its exit code. Exit code 0 means the vulnerability was successfully exploited — the test *passed* by demonstrating the absence of a defense. Codes 32–63 encode a discovered runtime parameter (`code-32`), and 64/65 signal that parameters were written to a temp file; both feed `variables.json`, which later cases consume through `-v` arguments. `report_gen` writes `results.dat` with the `test/sys_info.txt` header.

**Alternatives considered and rejected**
- *Reviving `doc/specification.tex` into HTML* — 2,052 lines predating the `bof→mss` / `ptt→mts` rename; needs full reconciliation against `configure.json` first. Rejected as a larger separate effort.
- *Generating `doc/test-catalog.html` from `configure.json`* — would eliminate drift by construction but adds a generator source file, a build step and its own tests. Rejected in favour of curation plus a coverage check.
- *A permanent Python test suite for the repo* — the repo has no runner; introducing one is a project-level decision that this plan should not make implicitly.
- *Stub doc pages* — leaves the planner's Phase 1 `doc/test-catalog.html` read with nothing to read.

**Explicitly out of scope**
- Fixing the `run-test.cpp:115` defect (recorded as a deferred issue instead, per the user's decision).
- `INTERNAL.md` — it is outside the planner's Write/Edit allowlist, so its drift cannot be corrected here. Flagged, not fixed.
