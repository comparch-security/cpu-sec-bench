### Approach

Ten surgical changes, all bench-side (1-6 the original cycle; 7-9 the review-driven extension the user directed after the first implementation round; 10 the post-implementation audit's Step 3 transition):

1. **Registry declarations for the mte build class** — `expect-results` gains `"99"` on the 214 records that delivered 99 on the mte stamp, are not `set-var` producers, and do not already declare it; the registry goes from 12 records declaring 99 to 226. The declaration follows the repo's existing precedent: 180 of 246 records already declare `"290"` (the CHERI-only SIGSYS) with the platform named in the meaning string; `expect-results` has never been class-conditional.
2. **`19` on `cfi-return-without-call` and `260` on the F2 record** — declarations, not signal-registration changes. `result.hpp:69-70` permits 19 ("declared only when a designed scenario reaches it"); the README and `doc/architecture.html` still say 19 is *never* declared, which contradicts the header — both published tables are amended by this plan (see `## Document Overrides`).
3. **PAC-aware RA-offset calibration** — a portable `STRIP_PAC(addr)` in every port header (aarch64: `xpaci` under `#ifdef __ARM_FEATURE_PAUTH`, identity otherwise; identity on x86_64, visualcpp, riscv64 and cheri_riscv64), used by the producer's slot comparison. The PA-signed saved LR strips back to the target label (probed: raw `0x007b000000400948` -> `xpaci` -> `0x0000000000400948` = the label, `cpu-sec-test-env/tmp/verification/2026-10-26-pa-probes-planner-hosted.log`).
4. **TRACE_RUN repair** — three `GET_SP_BASE` call sites (`lib/common/cfi.cpp:54`, `cfi/return-to-peer-mfunc.cpp:26`, `cfi/return-to-peer-vfunc.cpp:14`; no port defines `GET_SP_BASE`) take a copy of the offset and convert it with the sibling `GET_RA_ADDR`; nine further trace sites call `GET_RA_ADDR(ra_addr)` with no preceding assignment and therefore print `sp+0` — each gains one `ra_addr = <offset>;` line (the precedent is `cfi/return-to-peer-asmfunc.cpp:27-28`).
5. **Byte-reproducible guest image** — `cpio --reproducible` in `platform/riscv64-nemu-linux/build-image.sh:206`. GNU cpio's `--reproducible` is `--ignore-devno --ignore-dirnlink --renumber-inodes`: device numbers are zeroed, inodes renumbered deterministically in list order, and directory link counts pinned, so the host inode numbers the newc headers were leaking no longer reach the archive.
6. **Scratch-tree corpus build and clean provenance** — `build-corpus.sh` builds in `$OUT/build/<runset>/tree` (the recipe `run-native.sh:32-39` uses, outside the published per-runset venue directory) instead of swapping the derived registry over the tracked `configure.json` in the work tree; the bench-tree marker is captured once at the top, before any copy or derivation, and used by `sys_info.txt` and `corpus-manifest.py`. The work tree is never written, so the `-dirty` marker can no longer be produced by the platform itself, and a SIGKILL cannot leak a registry. A `flock` on the per-runset venue directory closes the same-DEST concurrency hazard that the swap removal does not.
7. **TRACE_RUN slot locator for `cfi-return-without-call`** — the trace address becomes a value-based scan for the saved return address (the `cfi/return-to-peer-asmfunc.cpp:16-32` precedent, with `STRIP_PAC`), not arithmetic on the record's frame-size variable: `GET_RAA_SP_OFFSET` is a no-op on POSIX, `fsize` is a 4-byte-unit count divided by `sizeof(arch_int_t)`, and the TRACE_RUN build's frame is not the producer's frame (measured: frame-size 4 prints `sp+2`, while the saved RA is at `sp+40` on x86_64, `sp+8` on aarch64 and `sp+40` on riscv64 — all inside `RA_POS_TEST`'s 0-60-byte window). The post-push trace pair joins the same `ra_offset >= 0` guard so a failed scan never dereferences the zero-initialised `ra_addr`. <!-- UPDATED: review finding return-without-call-trace-offset -->
8. **PAC-aware RA-slot scanners** — `STRIP_PAC` at the slot match in the two heap-memcpy records and in the fourth scanner, `cfi/return-to-peer-asmfunc.cpp:22` (the model Step 7 copies), plus an integer-domain `STRIP_PAC_VAL` for the heap-copy comparison; the implicit case stores the stripped value in the heap copy, the explicit case strips the matched word before storing it, and the asmfunc case compares the stripped slot with the (already stripped) `__builtin_return_address(0)`. Measured pre-fix on `enable_aarch64_pa=yes`: all three exit 1; post-fix the two heap-memcpy records deliver 0 (the attack lands — PAC does not defend an indirect jump to a stripped saved LR) and `return-to-peer-asmfunc` raises SIGILL (`260`; measured on a scratch copy carrying the planned strip — exit 132 locally, 16 `xpaci` in the binary), which the same step declares. ### Key decisions and alternatives

- **Per-record declarations, not a class-conditional registry field.** A field such as `expect-results-hwasan` would need scheduler code (`lib`/`scheduler`), a new documented field, and a second merge path in the require gate. The repo's own precedent (`290` declared on 180 records with "cheri capabilities enabled." as the meaning) already expresses "a code only this platform family can deliver"; the declaration text names the build class instead.
- **The 14 `set-var` producers keep `99` undeclared.** `lib/include/result.hpp:17-25` states the carve-out: declaring a calibration producer's failure constant would satisfy a dependent's `require` gate and run the dependent on a failed input. The producers' 99s stay class-dispositioned by the classifier's calibration-cascade section.
- **Declarations are evidence-driven, not blanket.** Only the 214 records observed at 99 receive it; the 14 non-producer records that delivered something else (0/16/21/260) keep their current declarations except the one F2 record, so a future 99 there is flagged rather than absorbed.
- **Insertion is a prepend.** The edit script rebuilds each `expect-results` object as `{"99": msg, **existing}`, so an existing block gains exactly one line and no existing line changes (measured shape for Step 1: 280 added / 2 deleted — 214 new entries, 31 records gain a new three-line block because they had no `expect-results`, and 2 records' previous last line gains a comma).
- **`19` declared rather than the SIGILL registered.** Registering `(NULL, ILL_ILLOPC, ACCERR, SIGILL)` would turn the PAuth authentication failure into `16` (`ACCERR`, "no permission to access the target address") or `21` (`FAULT_CONTAINED`) — meanings that describe memory faults, not an ISA-level authentication trap — and would add a second wildcard signal contract to a portable case. The diagnostic value is the honest one, and the header already sanctions it; the masking risk on the currently-clean lanes is recorded in `## Risks`.
- **Scratch tree rather than a hardened swap.** The swap's backup is taken from the work tree, so a leaked state is carried forward; trapping more signals only narrows the window. The scratch tree removes the write entirely.
